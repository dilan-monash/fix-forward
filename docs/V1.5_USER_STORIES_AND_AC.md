# FixForward v1.5 prototype — user stories and acceptance criteria

**Status:** prototype requirements for usability review, not a silent replacement for the approved Iteration 1 source of truth.

## US-H1 — Choose my goal first

**As a household user with a faulty appliance, I want to choose Repair, Compare costs, Recycle, or Help me decide from the first screen, so I can get to the task I came for.**

Acceptance criteria:
- all four choices are available in the first-screen hero;
- plain language explains the site without assuming recall knowledge;
- direct routes do not add a second redundant “choose action” screen after a clear check;
- every direct goal still passes through the applicable safety/recall gate.

## US-H2 — Identify my appliance without specialist knowledge

**As a user, I want to choose an appliance and optionally enter brand/model, so I can continue even if I do not know technical product details.**

Acceptance criteria:
- exactly the approved six families remain;
- category is unavailable until a family is chosen;
- categories are consistently ordered within each family;
- brand/model are optional;
- model help uses a visual example and says not to open/remove screws;
- changing family/category clears stale dependent result state.

## US-H3 — Understand a short safety question

**As a user who may not understand electrical terminology, I want a simple explanation and example, so I can answer from what I already noticed without testing the appliance.**

Acceptance criteria:
- question wording is short and product-relevant;
- every question has “What does this mean?”;
- help includes an example/pictogram and explicit do-not-test instruction;
- help is keyboard accessible and has a focus target;
- users can select Yes/No/Not sure from the help panel.

## US-H4 — Stop checking when I already saw a warning

**As a user who has already reported a warning or is unsure, I do not want to inspect the appliance further just to finish the form.**

Acceptance criteria:
- a decisive Yes/Not sure can show a safer-next-step action immediately;
- “I'm not able to check this safely” is available;
- serious warning blocks ordinary community repair/cost routes;
- possible recall remains higher priority than convenience;
- water ingress remains a serious stop-use warning under the current I1 baseline;
- heat/power caution cases remain differentiated rather than every Yes becoming the same severity.

## US-H5 — Find a practical repair option

**As a user who chose Repair, I want useful places and contact actions before research statistics, so I can decide where to contact.**

Acceptance criteria:
- location is optional; manual suburb/postcode remains available;
- map is inside FixForward and only loads when there are useful results;
- service cards lead with name/type/distance/address and available phone/hours;
- Call, Directions and Show on map appear only when supported;
- missing fields are not invented;
- main copy says to call/check before travelling;
- source/provenance sits under About this listing;
- serious-risk flow never displays an ordinary Repair Café result.

## US-H6 — Understand repair history visually

**As a user, I want a simple picture of what happened with similar appliances, so I can understand the evidence without reading a dataset report.**

Acceptance criteria:
- repair evidence appears after practical service results;
- stacked visual shows fixed / repairable with more work / other outcomes;
- actual counts and percentages are both visible;
- chart has an accessible text alternative;
- category history is never called the probability that this exact appliance will be repaired;
- sample/source/limitations are expandable rather than primary task content.

## US-H7 — Compare two known prices

**As a user with a repair quote and a replacement price, I want the difference shown clearly, so I can understand the upfront comparison without receiving financial advice.**

Acceptance criteria:
- manual cost inputs are the primary usable tool;
- invalid values produce inline, focusable errors;
- calculation is correct and neutral;
- visual bars retain exact dollar values;
- automatic AI/model price is not invented when governed evidence is insufficient;
- changing appliance identity invalidates a stale displayed comparison result.

## US-H8 — Recycle with uncertainty without unsafe transport advice

**As a user who wants to recycle but is unsure about a warning, I want a cautious way to contact a facility, so I am not left at a dead end.**

Acceptance criteria:
- serious/high-risk result does not route to ordinary facility listings;
- uncertain, non-recall recycle intent may show contact-first listings;
- transport warning says not to move an actively hot/smoking/leaking/damaged appliance until appropriate safety advice;
- facility acceptance is not claimed unless source evidence supports it.

## US-H9 — Keep my location optional and private

**As a user, I want to use current location only if I choose, so I can find nearby services without creating a saved location profile.**

Acceptance criteria:
- browser permission is requested only after the location button is activated;
- denying permission leaves manual search usable;
- exact coordinates remain in JS memory and are not posted to the FixForward API/Neon;
- no journey data is stored in localStorage/sessionStorage/cookies;
- map/privacy limitations are documented accurately.

## Scope decision

Before final Iteration 1 acceptance, BA/team/mentor must explicitly approve, defer or reject the prototype changes in this document. Older frozen acceptance criteria remain authoritative until that decision is recorded.
