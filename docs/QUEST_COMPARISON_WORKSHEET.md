# FixForward: local comparison worksheet

Use this worksheet for formative product exploration. **Quest is for children aged 7–12**; the existing adult guide serves a separate audience and task. A companion can join an optional story, but independent child play is the starting point for this exploration. This is not a controlled A/B experiment, an educational assessment, a marks prediction or evidence that either experience changes behaviour. No participant study has been conducted for this build or its creative refresh.

Start the local server using [QUEST_IMPLEMENTATION.md](QUEST_IMPLEMENTATION.md), then open both tabs:

- Child adventure: http://127.0.0.1:5502/quest
- Existing adult baseline: http://127.0.0.1:5502/

The local adult page displays **SYNTHETIC USABILITY TEST DATA**. Its recall example, repair counts and service locations are invented interface fixtures. They are not live records or evidence about a real appliance. Do not contact or visit those locations. The child missions are authored picture stories. Neither source supplies a real safety assessment.

## Before an observation session

For any later sessions involving children aged 7-12, use the course/institution's appropriate research and consent process, including guardian permission and the child's assent where required. Obtain the applicable adult-participant consent too. Explain that participation is optional and can stop at any point. Do not recruit or begin a child session merely because this worksheet exists.

Keep real appliances out of the child activity. Use the current short boundary: "Your adventure stays on screen. Real appliances need adult help." Avoid inserting adult instructions into every play decision. Do not request names, exact ages, photographs, household locations or private disclosures in the app. Manage any observer notes under the approved research process; this worksheet adds no product tracking.

Record only what is needed for this approved session:

Offer Guided or Challenge without assigning an age bracket. Let the participant choose. Provide reading or accessibility support when wanted, and record that support without treating it as failure. Record observed actions separately from your interpretation. Do not infer touch-device usability from a resized desktop browser.

## Child adventure: agency, clues and creative choices

Start with an invitation such as: "Pip and Flo have a story for you. Pick what you want to explore. You can ask for a clue, change your mind or stop." Allow an initial attempt before giving navigation instructions. Let the child choose whether to greet a character, open a mission or explore the book. If you help, note the exact prompt. Observe interest without assuming that more animation or more completions means greater engagement.

| Task or invitation | Observe | What happened / support used |
| --- | --- | --- |
| Start from the neighbourhood. | Can the child explain what they can do and start a chosen mission? What do they choose first? Does Pip/Flo dialogue clarify the invitation or add reading effort? | |
| Find something useful in the picture. | Can they open a clue using the picture or list, find it in the clue pocket and reopen it while planning? Do the short labels help? Do they understand the story is fictional? | |
| Make a plan with their preferred controls. | Can they drag or select an action and a plan space? Can a keyboard user find focus and activate the same controls? | |
| Continue after a choice that does not fit. | Do the explanation and retry control help them revise the plan? Which clue changes their decision? Do they feel comfortable using a hint? Do not force an error if none occurs. | |
| Try the same kind of appliance with different evidence: Flo's next home, then The quiet fan. | Does their explanation use the working/checked versus unassessed conditions, rather than just the fan picture? Ask "What changed in this story?" | |
| Use the outcome's story projector. | Can they switch between Before your choice and The next chapter, and describe what changed? Do they distinguish an arranged plan from work already finished? | |
| Sort one five-picture round. | Can they keep the current item and destinations usable, read conditions and distinguish clean packaging, collection checks and a reason to ask for help? Is an accidental drop understandable? | |
| Open the story passport and Discovery Book. | Do they understand earned versus unearned stamps? Can they open a new story or design a postcard for a completed one? Do they distinguish eight story stamps from discoveries found in sorting? | |
| Create a postcard if they want to. | Can they choose a theme and sticker and see their design change? Ask what they chose and why, without judging the style. Is downloading clearly optional? | |
| Return to a design and optionally save its picture. | Do they distinguish browser-saved choices from an SVG download? If they choose to download, can they locate and open the file with suitable support? Record an actual result, not only the button click. | |
| Place an earned decoration. | Can they choose and change its neighbourhood location with their preferred controls? Do they see this as making a fictional place their own? | |
| Try the secret envelope, only if they choose it. | Can they reveal Jo's report solo? If playing together, does the child keep control and contribute a choice? Companion availability is not a completion requirement. | |
| Try Less movement or requested reading support. | Are clues, expressions, next-step information and postcard controls still understandable? Do brief effects help them notice a change or distract them? | |
| Reach a short ending. | Without pressure, do they choose another story, explore the book or finish? Record their choice; continuing is optional. | |

Optional discussion: "What clue helped you most?", "What changed in your story?" or "Which part would you make your own?" For a warning story, ask whom they would tell and why. Do not direct every conversation back to a companion. Avoid treating confidence, reading speed, stamps, postcard downloads or decorations as proof of learning. No real appliance inspection or handling is part of the task.

## Adult baseline: a useful next step and clear uncertainty

Use a supplied **test scenario**, rather than entering the child's fictional mission as if it described a household appliance. The existing adult route is the preserved baseline, not the proposed future adult redesign.

| Task or invitation | Observe | What happened / support used |
| --- | --- | --- |
| Begin at the adult home page and select a relevant purpose. | Can the adult identify what the guide does and choose Help me decide, Repair it or Recycle it for the supplied task? | |
| Enter a category; leave unknown brand/model details unknown. | Are optional fields and uncertainty understandable? Is there pressure to invent information? | |
| Use a supplied safety scenario, including one "Not sure" answer. | Can the adult understand the question and identify a useful next step without being asked to test a real appliance? | |
| Interpret the resulting guidance. | Can they state the next action and what remains unknown? Do they distinguish an unavailable/no-match recall result from clearance? | |
| Inspect a synthetic service result if the task reaches that view. | Do they understand that item acceptance requires confirmation and that the displayed test location is not real? Do they distinguish a community event from a qualified repair service? | |
| Switch to Quest, then return to the existing adult tab without reloading it. | Are adult answers still present? Is it clear that child mission facts did not become adult answers? | |
